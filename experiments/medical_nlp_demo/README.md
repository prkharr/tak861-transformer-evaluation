# Medical claims NLP sequence demonstration

Import `notebooks/Medical NLP Demo/01_medical_claims_NLP_sequence_demo.ipynb` into Databricks, fill the seven empty `sf_options` fields in cell 1, and run its seven cells in order. Requires Spark with the Snowflake connector, numpy, pandas, scipy, scikit-learn, joblib and matplotlib. No model download, internet access, GPU or additional repository files are required at runtime. This notebook is independent of the five AutoML notebooks and does not modify their artifacts.

The default demonstration selects at most 100 patients by a deterministic label-independent hash and uses each patient's latest snapshot from the original V63 MODEL_DATA universe. One extraction query aggregates diagnosis and procedure code occurrences from MEDICAL_EVENTS_LATEST. A code occurrence is counted once per distinct MEDICAL_EVENT_ID per month and code. This is code-event activity, not unique overall claim utilization. Outcome labels are neither retrieved nor used.

Twelve calendar bins run oldest to newest: eleven previous months plus the snapshot month through END_DT. The final month may be partial. Current DX/PX descriptions supply the text. Ambiguous mappings use the lexicographically first description and are audited; historical mapping/ingestion-as-of equivalence is not asserted. No pharmacy data or clinical notes are used.

Count-weighted description unigrams and bigrams are constructed with sparse matrix multiplication, preserving medical negation words. The 256 most frequent terms in the demonstration are retained, then sublinear TF-IDF with L2 normalization is fitted across its patient-months. The resulting float32 tensor is patient × 12 × terms (at most 1,228,800 bytes at defaults). Term counts and dates are based on actual source events, not replication of a static vector. No-activity patient-months remain zero. Zeros are not proof of complete history or disease absence.

Features rank by mean TF-IDF across demonstration patient-months. Patient/month coverage, mean absolute temporal change and recent-minus-early TF-IDF accompany that score. These are descriptive quantities, not predictive importance, clinical significance, lift or evidence of model improvement. The vocabulary and IDF are fitted on the entire demonstration; any predictive follow-up needs separate patient-level splits and TRAIN-only fitting.

Cells 4–5 show source/mapping coverage, tensor dimensions, ranked terms, aggregate monthly trajectories and a heatmap. Cell 6 saves aggregate CSVs, a PNG and a receipt under the configured local scratch folder. Cell 7 exports a private reusable feature package: ordered feature list, float32 tensor and activity masks, patient/snapshot row index, frozen TF-IDF state and a hash manifest/feature contract. Keep patient-level files in the authorized environment. No credentials are exported. Local outputs do not survive cluster replacement; copy the private package to approved persistent storage and download only the aggregate presentation results if needed.

For future extraction, import `make_nlp_sequence` from the exported `medical_nlp_transform.py` and call `make_nlp_sequence(new_aggregates, CONFIG, frozen_state=loaded_state)`. This transforms with the saved vocabulary, selected-term order and IDF without refitting, and stops on description changes for previously seen codes. New codes can contribute known vocabulary terms; unknown words are ignored. Preserve the reference version and package versions for reproducibility. The feature list's `feature_index` is the tensor column order; descriptive `rank` is a separate field. To use this representation with a Transformer, align patient/snapshot keys and chronological orientation, set the input projection width to the exported term count, and define masking intentionally. Activity masks do not establish enrollment coverage. This is a new feature representation requiring an adapter, not a drop-in replacement for the existing count/AutoML input contract. Refit on TRAIN only before any predictive evaluation.

`event_id_column` is configurable, defaulting to MEDICAL_EVENT_ID from the supplied medical extraction procedure. It must be a genuine stable event identifier; do not replace it with a row-number or guessed key. Schema preflight checks it before extraction. The local validator is `python -m experiments.medical_nlp_demo.validate_demo` on the mandated interpreter with the existing four package-runtime paths; it adds `work/sql_audit` for SQL parsing and records all package versions in `local_validation.json`.
