# Internal sanity review — raw AutoML tensor revision

This is a Codex code review, not a Claude approval. The user explicitly deferred Claude review and authorized the Git push. Exact source/notebook identities and local test results are recorded in build_manifest.json and local_validation.json.

Notebook 01 now includes the historical raw AutoML extractor derived from the supplied complete procedure bodies. It reads only current raw claim/demographic/reference sources; no legacy AutoML model, learned mapping, feature-summary or prediction table is required. Labels are excluded from source requests and SQL. Original RESP-dependent pruning, target-derived type conversion/caps and importance selection are omitted. The bounded vocabulary is chosen using distinct TRAIN-patient category frequency without labels. These revised raw definitions are not claimed numerically equivalent to the old 261 features.

Inspection corrected RX population filters: paid events drive ordinary RX features, while transaction-result counts retain all results. Diagnosis aggregate counts retain all medical events. Historical requests enforce individual inclusive 12-month windows and the recovered four-to-one-month recent window. Response validation rejects missing/duplicate keys, invalid counts and event maxima outside the requested window. Generated SQL parses in the Snowflake dialect; schema access and warehouse execution have not been tested here.

AutoML tensors use genuine per-date values, not repeated current snapshots. No-claim windows remain missing with explicit indicators; patients and count tokens remain in all matched arms. Static fusion includes the current availability indicator; temporal fusion includes it at every step. Source-event presence does not establish continuous coverage. Current LATEST source/reference attributes have unresolved historical availability. Twelve rolling windows may span about 23 months of event history.

All 1,028 count candidates remain available for TRAIN selection. AutoML's declared 512-column input resource cap is separate from final feature-count selection and can exclude rare signals. Feature quality checks, transforms and proxy rankings are fitted within patient-grouped TRAIN folds. Validation lift drives checkpointing and scheduling; top 10% is a declared default, top 20%/30% secondary. TEST remains gated and retrospective. Patient-cluster bootstrap uses exact capacity, patient multiplicity and model-minus-reference direction.

Memory changes replace dense float64 intermediate tensors with blocked calculations; synthetic parity checks compare against the original dense formulas. Integration checks cover all five generated notebook cell sequences, all registered arms, checkpoint restoration, missing AutoML histories, input/cache hashes and the TEST gate. No private clinical tensors were extracted or models trained here, so no new clinical result or runtime guarantee is implied.
